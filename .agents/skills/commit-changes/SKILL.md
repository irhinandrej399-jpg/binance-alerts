# Осмысленные коммиты

Самостоятельно выбирай момент для коммита без отдельного подтверждения каждого коммита. Ориентируйся на завершённое логическое изменение: фичу, исправление или связанное обновление документации. Не коммить каждую мелкую правку и не накапливай независимые задачи в одном большом коммите.

## Подготовка

- Проверь git status и diff, включая уже подготовленные изменения. Определи, какие файлы относятся к текущей задаче. Не захватывай несвязанные пользовательские изменения.
- Убедись, что выполнены проверки, необходимые для изменения. Для документации достаточно проверки содержимого, ссылок и git diff --check; не запускай тесты приложения без причины.
- Если задача состоит только в подготовке TDD-тестов стадии Red, проверь ожидаемую причину падения и явно отрази эту стадию в сообщении. Не выдавай такие тесты за реализованное поведение.
- Проверь выбранные файлы на секреты и локальные артефакты. Добавляй в индекс конкретные файлы или связанные каталоги; затем проверь git diff --cached и git diff --cached --check.

## Сообщение и фиксация

Пиши сообщение на русском языке. В заголовке конкретно укажи изменение; при необходимости в теле объясни причину и важные решения. Избегай заголовков вроде «правки», «обновление» или «фикс» без пояснения.

Например: «Сохранять рыночные цены в outbox перед публикацией в Kafka».

Создай коммит и проверь результат через git status и git log -1. Не переписывай существующую историю без запроса пользователя. Само применение навыка не даёт дополнительного разрешения на push: учитывай действующие инструкции и авторизацию в разговоре.

В ответе кратко укажи хеш и смысл коммита, а также выполнялась ли отправка в remote.
