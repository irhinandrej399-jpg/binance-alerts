# Изменение gRPC API

> Статус: заготовка на будущее. Сейчас взаимодействие сервисов
> построено на Kafka. Наличие этого навыка не является причиной
> добавлять gRPC в проект.

Используй этот навык для запрошенного изменения gRPC API. Не добавляй gRPC или новый синхронный вызов только ради применения навыка. Если подходящего API ещё нет, сначала определи с пользователем конкретного вызывающего, владельца данных и причину необходимости синхронного ответа.

## Определи область изменения

- Прочитай инструкции затронутых сервисов и доступную документацию контрактов.
- Найди исходные `.proto`, реализацию сервера, вызывающих клиентов и существующие контрактные тесты.
- Найди принятую команду генерации и версии генераторов в документации или настройках сборки. Если команды нет, явно сообщи об этом; не выдумывай её и не редактируй сгенерированный код вручную.
- Уточни ожидаемое поведение: входные данные, результат, ошибки и требования к совместимости. Не расширяй изменение на несвязанные RPC.

## Проверь контракт и поведение

- Оцени совместимость формата сообщений и поведения отдельно: добавление поля само по себе не гарантирует совместимость старых клиентов.
- Не меняй номера существующих полей и не используй повторно удалённые номера. При удалении полей резервируй их номера и имена. Для изменений типов, enum, presence, package и имён RPC проверь последствия для существующих клиентов.
- Сохраняй различие между отсутствующим значением и значением по умолчанию там, где это влияет на бизнес-логику.
- Для затронутых вызовов проверь валидацию, коды gRPC-ошибок, передачу deadline и отмены. Оцени повторные попытки с учётом побочных эффектов и идемпотентности; не добавляй повторы автоматически.

## Выполни изменение по TDD

- Сначала добавь или расширь тест наблюдаемого поведения и проверь его ожидаемое падение.
- Если тест требует нового сгенерированного интерфейса, сначала измени `.proto` и выполни генерацию, затем получи падение теста из-за отсутствующего поведения. Отличай ошибки сборки от проверки поведения.
- Обнови сервер и затронутых клиентов, затем выполни необходимый рефакторинг.
- Запусти принятую генерацию, тесты затронутых сервисов и существующие проверки контрактов и совместимости. Для независимо обновляемых сервисов проверь нужные сочетания старого и нового клиента и сервера доступными средствами.
- Проверь итоговый diff: нет ли несвязанных изменений и случайной перегенерации из-за другой версии инструмента. Обнови документацию контракта, если она затронута.

## Отчёт

Кратко укажи, какие RPC и потребители изменились, какие проверки выполнены и каковы результаты. Для несовместимого изменения опиши требуемый порядок обновления сервисов. Если генерация, тест или проверка совместимости недоступны, явно укажи ограничение и не заявляй успешную проверку.
