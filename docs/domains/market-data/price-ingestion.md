# Приём и сохранение рыночной цены

Статус: реализован первый домен Market Data. Тесты нормализации используют fake outbox;
долговечность и уникальность отдельно проверяются на PostgreSQL.

## Ответственность

Одна операция принимает raw JSON сделки Binance Spot `aggTrade`, проверяет нужные поля,
формирует PriceObserved v1 и сохраняет запись в outbox. Цена — цена сделки этого потока,
не bid/ask, не средняя цена и не обещание исполнения покупки.
Market Data владеет адаптацией источника. Будущий Alerts владеет правилами и порогами;
Identity и Notifications в этом домене не участвуют. Других реализованных сервисов нет.

Вне обработчика цены: WebSocket lifecycle, управление набором инструментов, публикация
в Kafka и очистка outbox. Они реализованы отдельными адаптерами и сценарием relay;
см. [архитектуру](../../architecture/market-data.md) и [outbox-relay](outbox-relay.md).
Динамический набор описан отдельно в [instrument-tracking](instrument-tracking.md); backfill пока не реализован.

## Вход

[Документация Binance Spot — Aggregate Trade Streams](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/ws-streams/~), проверено 2026-10-18.
Поток `<symbol>@aggTrade`, raw-формат, время в миллисекундах по умолчанию.
Микросекундный режим и combined-envelope в этой версии не поддерживаются.
Адаптер подписывается через raw endpoint `/ws` на сконфигурированный или сохранённый динамический набор пар.

Синтетический пример:

```json
{"e":"aggTrade","E":1770000000125,"s":"BTCUSDT","a":12345,"p":"60000.01000000","T":1770000000123}
```

## Выходной контракт

Исходный Go-контракт: [prices.go](../../../services/market-data/internal/prices/prices.go).
Событие сохраняется в outbox и затем передаётся в топик `market.prices.v1` (настраивается).
Ключ Kafka — UTF-8 символ пары `BTCUSDT`. Порядок JSON-полей не значим.

```json
{
  "schema_version": 1,
  "event_type": "PriceObserved",
  "event_id": "binance:spot:aggTrade:BTCUSDT:12345",
  "source": "binance",
  "market": "spot",
  "symbol": "BTCUSDT",
  "price": "60000.01000000",
  "occurred_at_ms": 1770000000123,
  "source_event_id": "12345"
}
```

Record содержит EventID, Key и Value; EventID совпадает с event_id внутри Value.
Успех Handle означает успешный Append, а не доставку в Kafka.

## Правила

- **MD-01:** один корректный raw aggTrade вызывает одно сохранение. Время берётся
  из `T` (время сделки), а не `E` (время события) или локальных часов.
- **MD-02:** цена — положительная строка формата `[0-9]+(\.[0-9]+)?` с ненулевой
  цифрой. Сохранять представление точно. Float, экспонента, знак, пробелы, NaN,
  Infinity и JSON number вместо строки не допускаются.
- **MD-03:** обязательны `e=aggTrade`, непустой `s` из `[A-Z0-9]+`, `a` — JSON integer
  от 0 до int64 max, `T` — положительный JSON integer до int64 max и корректный `p`.
  Отсутствие/null не заменяются значением по умолчанию. Некорректный JSON, несколько
  JSON-значений, неверные типы, combined-envelope, служебное сообщение и другой тип
  события возвращают ErrInvalidMessage без Append. Неиспользуемые поля допускаются.
  Синтаксическая проверка пары не подтверждает наличие пары на бирже.
- **MD-04:** source_event_id — точная десятичная запись `a` без float-преобразования.
  event_id = `binance:spot:aggTrade:<symbol>:<a>`. Он стабилен для повторов и различается
  для разных пар с одним a.
- **MD-05:** повторные, запоздавшие сделки и сделки с неизменной ценой передаются в
  Append. Обработчик не хранит последнюю цену и не сортирует. SQL outbox дедуплицирует
  event_id, пока запись хранится; Kafka-потребитель всё равно должен учитывать повторы.
- **MD-06:** ошибка Append возвращается с сохранением errors.Is; внутреннего повтора
  в Handle нет. Результат записи при сетевой ошибке может быть неизвестен. Транспортный
  адаптер повторяет тот же вход с тем же идентификатором.
- **MD-07:** заранее отменённый контекст возвращает ошибку без Append. Исходный
  контекст передаётся в хранилище, его ошибки отмены не скрываются.

## Сценарии

| ID | Вход / состояние | Результат |
|---|---|---|
| S01 / MD-01 | Сделка, E отличается от T | Правильный контракт, время T, ключ пары |
| S02 / MD-02 | Малая/большая дробная цена, конечные нули | Точная строка цены |
| S03 / MD-03 | Плохой JSON, envelope, служебный/иной event | ErrInvalidMessage без Append |
| S04 / MD-03 | Отсутствие/null/неверный тип поля | ErrInvalidMessage без Append |
| S05 / MD-02 | Ноль, отрицательная цена, иной формат | ErrInvalidMessage без Append |
| S06 / MD-04 | a=0, a>2^53, a=int64 max | ID без потери точности |
| S07 / MD-04 | Один a у BTCUSDT и ETHUSDT | Разные event_id и ключи |
| S08 / MD-05 | Та же сделка дважды | Два вызова Append с тем же event_id |
| S09 / MD-05 | Новая, затем более старая сделка | Обе переданы, исходное время сохранено |
| S10 / MD-05 | Разные сделки, одинаковая цена | Обе переданы с разными event_id |
| S11 / MD-06 | Append ошибся; повтор успешен | Ошибка, затем успех; ID тот же |
| S12 / MD-07 | Контекст уже отменён | Ошибка отмены, Append не вызывается |
| S13 / MD-07 | Deadline и ошибка отмены хранилища | Контекст и ошибка сохранены |
| MD-03-extra | Новое неиспользуемое поле, JSON whitespace | Успешная нормализация |

Команда из корня: `go test ./services/market-data/internal/prices`.
Гарантии PostgreSQL/Kafka проверяются командой `make integration`.
