# Доставка outbox в Kafka

## Правила

- OB-01: повтор event_id не создаёт вторую запись в PostgreSQL.
- OB-02: пакет читается по id, подтверждение отмечается только после успеха Publisher.
- OB-03: ошибка Publisher или БД откатывает пакет. Ack Kafka без commit допускает дубль.
- OB-04: одновременно доставляет один relay на БД, включая разные процессы.
- OB-05: отменённый контекст не начинает отправку; периодические циклы завершаются по отмене.
- OB-06: чистятся только опубликованные записи старше retention, ограниченным пакетом.

## Сценарии

| ID | Вход | Результат |
|---|---|---|
| OB-T01 | Два события | Вызовы Publisher в порядке записей, успех |
| OB-T02 | Publisher ошибся на первой записи | Ошибка наружу, вторая не отправлена |
| OB-T03 | Контекст отменён | Нет вызовов Publisher |
| OB-T04 | Повтор сохранения одной сделки | Одна SQL-запись |
| OB-T05 | Ошибка после ack первой из двух записей | Весь пакет остаётся pending, после повтора доставлены обе |
| OB-T06 | Конкурирующие relay | Второй не публикует захваченный пакет |
| OB-T07 | Истёкшие sent и pending | Удалены только sent |

OB-T01–03 — unit. OB-T04–07 — интеграция с отдельной тестовой БД.
Передача по реальному протоколу Kafka проверяется отдельным интеграционным тестом.

## Транспорт и HTTP

WS-01: подписаться на сконфигурированные пары, принимать только aggTrade, ack не является ценой.
WS-02: повторять текущее сохранение при временной ошибке, завершать чтение по отмене.
WS-03: после разрыва повторно подключиться и подписаться; служебная ошибка означает разрыв сессии.
HTTP-01: GET /healthz — 200, GET /readyz — 200/503 по зависимости, POST на них — 405.
Их тесты используют локальный WebSocket server и httptest; живой Binance не нужен.
